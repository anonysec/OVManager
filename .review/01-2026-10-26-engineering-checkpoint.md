## Live-event invalidation, request fan-out, and polling review

- The collector's `updateSnapshot` returns change flags: unchanged snapshots publish no domain event; a single pass can publish at most one `nodes` and one `users` invalidation when their respective state changes. SSE payloads contain operation/timestamp metadata rather than domain records.
- `LiveContext` now forwards parsed payloads to exact-topic and synthesized `*.changed` subscribers. Ordinary `users`/`nodes` events no longer become global `tick`s; `ready` and disconnected fallback ticks remain full resynchronizations. Existing direct `users.created/deleted` and `nodes.created/deleted` topics are subscribed by the relevant pages for compatibility.
- A demonstrated dashboard fan-out issue was narrowed: `ServerStats` previously loaded its full metrics/activity/users/nodes bundle for either domain event. It now refreshes a user slice on user events (connection-only: users + owner metrics; other/legacy operations also update notifications, activity, and owner top users) and a node slice on node events (node list plus per-node status probes). Generation counters prevent older full/sliced responses from overwriting newer user, node, metrics, or probe results. A same-cycle user+node regression test asserts only the affected requests are made.
- Sidebar now skips `/users/` refresh for `op:"connections"`, while retaining reset/create/delete/restore and legacy no-op metadata refreshes. UserManagement still needs a user-list update for connection counts. Identical in-flight GET URLs are coalesced by the API client's in-flight map; the API regression test verifies one underlying fetch for concurrent identical GETs and that rejected GETs can retry. This is not a persistent response cache: later sequential calls still reach the server.
- `createQueuedRefresh` deliberately retains one trailing pass when another invalidation lands during a request. This is a race-safety guarantee, not a debounce and not a dropped duplicate event; tests cover coalescing and the trailing refresh. No arbitrary delay was introduced.
- Reconnect recovery is explicit: stream `ready` causes a full resync; a stream 401 dispatches the auth-expired event; when disconnected, the provider emits 8-second fallback ticks and ServerStats has its visible-only 30-second fallback. UserManagement keeps a visible-only 10-second poll while the stream is healthy because user CRUD writers currently lack complete invalidation publication. Provider fallback ticks now pause while the document is hidden; visibility restoration triggers an immediate resync, covered by a focused test.
- Remaining polling/fan-out questions: NodeManagement still polls detailed node statuses every 30 seconds, and StreamChart independently polls metrics history every 30 seconds. ServerStats also requests the 24-hour history for its KPI on initial/full refresh and user invalidation; the in-flight cache only collapses overlap, so those consumers can make sequential requests to the same endpoint. Their cadence/data needs were left intact rather than introducing a delayed debounce or unverified cache.

## Confirmed changes in the current worktree

1. **In-flight GET rejection cleanup.** Replaced an unobserved `.finally()` chain with fulfillment/rejection cleanup handlers; the frontend test covers retry after a failed GET.
2. **Origin validation hardening.** Mutating requests now compare scheme, normalized host, and effective port; honor `X-Forwarded-Proto` only behind `TRUSTED_PROXY`; reject malformed, explicit-empty, duplicate, and fragment-bearing Origin values. An absent Origin remains allowed for non-browser clients. Go tests cover proxy, scheme, host, port, and malformed cases but are unrun.
3. **Consistent session-name resolution and diagnostics fan-out.** Metrics and live snapshots use a shared ID/name/suffix resolver that gives a known username precedence over a colliding numeric ID, including after node-suffix normalization. Per-user session and auth-event filtering use the same mapping. Login diagnostics use one `GetUserSessionDiagnostics` fan-out for both session details and the health row; fan-out timeouts/errors retain their configured node row and mark the response partial instead of silently disappearing, and recommendations avoid treating partial counts as complete. Added regression coverage for numeric-name/ID collisions, timeout attribution, and one-call fan-out. Go tests are unrun.
4. **Subscription handling.** Subscription pages/downloads send `Cache-Control: no-store`; rate-limit eviction uses `sort.Slice` and enforces the cap after adding a new bucket. Go tests cover the cache headers and oldest-bucket eviction but are unrun.
5. **User sessions journey and diagnostic status accuracy.** `GET /users/{uuid}/sessions` uses the node diagnostics implementation with `hours` bounded to 1–720; the modal renders session common names and counts. Disconnect calls `/kick`, with the legacy `/disconnect` retained as an alias. Unavailable global-registry data is distinguished from a genuine empty registry. Fan-out failures/timeouts are retained as unavailable nodes, their counts render as unknown rather than zero, and an accessible warning explains that totals include only reachable nodes. Added Go integration/unit coverage and three focused UI tests for registry states and partial results; latest frontend verification passed, Go tests are unrun.
6. **Clean-checkout embed fix.** Restored `internal/webfs/dist/.gitkeep` and kept it through Makefile staging/clean.
7. **README accuracy.** Clarified fixed `/api/` and `/health` routes, decoy 404s, and public subscription UUID bearer links; routing behavior was not changed.
8. **Additive numeric-ID request aliases.** Added explicit `/users/id/{id}/...` aliases and `/nodes/ovpn/id/{user_id}/{node_id}` for authenticated user/admin workflows, retaining UUID routes and their handling for numeric-looking UUIDs. Frontend callers prefer safe numeric row IDs and fall back to UUIDs. Restore, deep links, and public subscription URLs remain UUID-based because row IDs can change on restore. Integration tests cover valid, invalid, missing, unauthorized, and correct-row cases; Go tests are unrun. These IDs reduce one example path from 52 to 21 characters (31 saved), a small readability/logging benefit rather than material bandwidth savings; neither ID is an authorization secret.
9. **Scoped SSE refreshes and hidden fallback polling.** Forward SSE payloads to subscribers, avoid global dashboard reloads for domain events, filter Sidebar refreshes for connection-only operations, and split ServerStats user/node invalidations into targeted requests with request-generation guards. Add regression tests for operation metadata, paired user/node bursts, and hidden fallback/resume behavior. The 8-second provider fallback no longer refreshes while the tab is hidden.
10. **Trusted-proxy external URL scheme and HSTS.** `baseURL` (used by subscription links and settings fallback URL) and HSTS now treat `X-Forwarded-Proto` as authoritative only when `TRUSTED_PROXY=true`, while preserving direct TLS. Tests cover untrusted spoofing, trusted and comma-separated forwarded schemes, and direct TLS; Go tests are unrun.
