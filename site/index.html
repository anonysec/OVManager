Your own OpenVPN panel.

OVManager is a self-hosted admin panel for OpenVPN. It keeps the user list, quotas and expiry dates on one box, and drives one or many VPN servers through a small agent called OVNode.

No hosted service, no account with anyone, no license key. You run the panel on a VPS, you own the data, and the whole stack is MIT-licensed.

Install it Read the wiki

Install

One command on a fresh Debian or Ubuntu server, run as root (or with sudo). It installs the panel, generates a random secret URL path, sets up TLS and prints a one-time claim key.

Honest status: no release artifacts published yet

v1.0.0 is the first release and nothing is on GitHub Releases or tagged yet. The command above is the project's real entry point, but the installer downloads a verified release archive and checks its SHA-256 before it extracts anything — it fails closed rather than installing an unverified tree. Until those artifacts are published, the download step cannot succeed, and the working path today is a from-source install (see install from source).

Choose Install (native, systemd + a virtualenv) or Install with Docker. Defaults are safe and ask nothing: port 2095, admin user admin, self-signed TLS, random URL path. Full walkthrough, unattended flags and the first-login flow: Install & first login.

What you get

  • Users, quotas, expiry

    Per-user traffic quota in GB (empty means unlimited), an expiry date, a simultaneous-device limit and searchable tags. Defaults for new users live in one place.

  • One panel, many nodes

    The panel connects out to every VPN server; nodes never call back. Move or replace the panel and the VPN servers never notice.

  • Claim-key first run

    The installer mints no password. It prints a one-time claim key, you choose the owner password in the browser, and it is stored as a hash in the database — never in .env.

  • A hidden panel

    The panel is served under a random URL prefix and answers an empty 404 everywhere else, so internet scanners see nothing to poke at.

  • TLS either way

    Self-signed by default, so the first start is encrypted with no domain. Switch to Let's Encrypt from the panel or with ovm https --domain.

  • Verified backups

    ovm backup writes a checked database bundle, a daily timer can keep it fresh, and a scheduled backup can push the newest copy offsite over SSH.

  • Telegram alerts

    Optional bot that messages the owner about users near or over quota, and once per node outage — then once more when the node is back.

  • One operator CLI

    ovm status, doctor, logs, backup, restore, update, rollback and a recovery menu, all with stable exit codes.

Next steps

  1. Install the panel

    Run the installer, open the printed URL, paste the claim key and choose the owner password. Save that URL — it contains the secret path. Install & first login

  2. Connect a VPN node

    The panel does nothing until a node is attached. Same server, or a separate one — two commands and a form. Adding nodes

  3. Create a user

    Name, expiry, quota, device limit. The panel then hands you a .ovpn file or a subscription link. Users & subscriptions

  4. Keep it healthy

    Watch traffic, renew certificates before they expire, and take backups you have actually restored once. Traffic limits · TLS · Backups
