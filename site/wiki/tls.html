TLS certificates

There are two certificates in this system and they are not the same thing: one protects the panel in your browser, and one protects the panel's connection to each node.

The panel's certificate

A fresh install uses a self-signed certificate. The connection is genuinely encrypted; the browser just cannot tell who issued the certificate, so it warns once. Click Advanced, then Proceed. There is no plain-HTTP option to fall back to.

The installer's certificate carries the server's public IP as its common name and has no subject alternative names. That is deliberate — it is the reason the panel's own health check pins the certificate file rather than checking the hostname, and the reason a healthy panel is never reported as unreachable.

Or from the panel: Settings → TLS shows the current mode, the source, who issued it and how long it has left, and offers the same options — upload a key and certificate, generate a temporary self-signed one, or request a renewal for a domain. A certificate change needs a restart, and the panel offers to restart itself and reconnect the page.

Let's Encrypt issuance runs through acme.sh and needs port 80 reachable for the standalone challenge. If something else is already listening on 80, stop it or stay on a self-signed certificate for now.

The node's certificate

Each node serves its sync API over TLS too. The node installer never offers plain HTTP, because the API key travels in a header on every request — in cleartext that would be handing out the node.

What the panel does about it:

  • TLS is verified strictly first. A node using a self-signed certificate fails that check.
  • On that failure the panel retries once without verification and warns loudly — once per node, not once per request — as a standing reminder to move that node to Let's Encrypt.
  • The TLS switch on the node entry in the panel must match what the node is actually doing. A mismatch produces a silent connection failure, which is one of the usual causes of a node that stays red.

The node's own OpenVPN server certificate is a separate thing again, and the panel can ask a node to renew it and reports the new expiry. Nodes also show their certificate expiry in ovn status.

Watching for expiry

  • ovm tls-status on the panel — read-only, no restart.
  • ovn status on each VPN server — health plus certificate expiry.
  • Settings → TLS in the panel — the same panel information with the renewal buttons next to it.
