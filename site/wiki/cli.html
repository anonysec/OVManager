CLI reference

ovm (alias ovmanager) is installed with the panel and refreshed on every update. Run it with no arguments for the same list you find here.

Everything needs root

Every ovm command — including the read-only ones — reads .env, which holds the secret panel URL path and the install configuration. So run sudo ovm <command>. The only exceptions are ovm, ovm help and ovm --help, which print usage without loading anything.

The panel itself needs no root: any account can log in to the web UI.

The installer

install.sh answers to subcommands and to three flags. The flags are deliberately few: everything that shapes an install is an OVM_* variable, and the same variable is the interactive wizard's default, so a scripted run and a wizard run cannot disagree.

Env vars the installer reads.
VariableValues
OVM_MODEnative or docker
OVM_PORTThe panel port
OVM_PATHThe URL prefix, or root
OVM_ADMIN_USERThe admin login name
OVM_TLSself, le, le-ip or custom
OVM_TLS_DOMAINThe domain for Let's Encrypt
OVM_TLS_KEY / OVM_TLS_CERTPaths for a custom certificate
OVM_PUBLIC_URLPins the host used in subscription links
OVM_VERSIONPins a release version
OVM_REPOPoint source downloads and update pulls at a fork, e.g. myorg/OVManager

Deprecated but still accepted, each printing what replaces it: -p/--pass, --mode, --tls 1|2|3|4, --tls-domain, --tls-key, --tls-cert and -i.

It also takes --install-dir and --data-dir, and reads OVM_ADMIN_PASS for the password. Some commands stay host-side by necessity — logs, reset-password and reset-urlpath need a journal and a host .env that a container does not have, as do update, uninstall, rollback, recovery and certificate issuance.

On each VPN node

The node agent installs its own CLI, ovn (alias ovnode). With no argument it opens a numbered menu; every menu item is also a plain command with a stable exit code, so it is scriptable.

On the VPN server.
CommandWhat it does
ovn statusAgent, health, version and VPN state. --all also shows node, mode, port and TLS.
ovn credentialsNode name, API key and the panel bundle. Read-only.
ovn start | stop | restartControl the node agent service.
ovn restart-vpnRestart or reload OpenVPN.
ovn logs [N|-f]The last N log lines (default 100), or follow live.
ovn backup [--keep N]Archive the node data and PKI now. --keep sets retention; default 14.
ovn auto-backup on | off | statusDaily backup through a host timer, at 03:30.
ovn restore [name]List the archives, or restore one by name.
ovn tlsShow or replace the node's certificate.
ovn doctor [--fix]Health check across agent, VPN, disk, certificate and backups. --fix applies the safe repairs.
ovn updateStaged update with a verified safety snapshot first.
ovn rollbackRestore the newest pre-update code snapshot.
ovn recover-updateRecover an interrupted update transaction.
ovn completionInstall bash completion for ovn.
ovn uninstall [--purge]Remove OVNode. Data is kept unless --purge.

ovn update and ovn uninstall are implemented in the node's installer, so each exists in exactly one place. The installer itself takes three flags — -y/--yes, --docker and -h/--help — and everything else is an OVN_* variable; older flag spellings still work but print what replaces them. An unattended run reports its outcome as an exit code: 0 ok, 1 error, 2 usage error, 3 already installed, 4 not installed.

See the OVNode repository for the full OVN_* list and the node's runtime settings.
