Adding nodes

The panel is the control plane; each OVNode is a VPN server. Nodes never call the panel — the panel connects out to them.

Pick a topology

  • One box — panel and node on the same VPS. The easiest option, and plenty for personal use and small teams. The panel's Ready card prints a ready-to-paste command with the API key already filled in.
  • Panel here, VPN servers there — install a node on each VPN server and register them all in the one panel. Adding a node never changes the panel install.

Because the direction of travel is always panel → node, you can move or replace the panel at any time without touching the VPN servers.

1. Install the node agent

On the VPN server (not the panel server, unless you are doing the all-in-one setup):

OVNode is a separate project: github.com/anonysec/OVNode.

The wizard's questions

QuestionAnswer
Node name A short id like eu-1. This must match the name you type in the panel exactly. Renaming later orphans the old data folder, so pick once.
Service portEnter (2083).
OpenVPN ports Enter (1194). Add 443,8443 if your users are on networks that block VPN ports — clients fail over automatically.
API key Leave blank to auto-generate a strong one. Copy it from the summary.
ModeNative on a normal VPS; Docker if you prefer containers.
TLS Self-signed for the first node (then turn TLS on in the panel). Let's Encrypt once you have a domain pointed here. Plain HTTP is not offered — the API key would travel in cleartext.

The summary the panel needs

Node      eu-1
Address   203.0.113.10        <- the server's PUBLIC IP
Service   https://203.0.113.10:2083
API key   abc123...           <- copy this

Private vs public IP. If the summary shows a 10.x or 192.168.x address, the server is behind NAT (common on some clouds). Use the server's public IP in the panel instead.

Unattended

The installer takes three flags — -y/--yes, --docker and -h/--help — and every other setting is an OVN_* variable (OVN_NAME, OVN_KEY, OVN_PORT, OVN_VPN_PORTS, OVN_PROTO, OVN_TLS, OVN_TLS_DOMAIN, OVN_IPV6, OVN_NO_NAT, OVN_REPO). Older flag spellings still work but print what replaces them. Keep the key it prints (or the one you passed) — the panel needs it next.

2. Register it in the panel

Go to Nodes → Add Node and fill the form, or paste the ovnode:// bundle the node installer printed — the bundle fills every field at once. It looks like: 

ovnode://eu-1@203.0.113.10:2083?key=...&tls=1
FieldValue from the node summary
Nameeu-1 — an exact match, not a similar name
AddressPublic IP or hostname
Port2083 — the sync API port, not the OpenVPN port
API keyThe generated key, pasted exactly, with no stray spaces
TLSon — the node installer always encrypts (self-signed or Let's Encrypt)
OVPN port / protocol1194 / whatever the node summary says

Use Test connection before saving if you want an immediate answer. Once saved, the row turns green within seconds and shows the node's version and user count.

All-in-one: panel and node on one box

Same two steps, with a shorter second one. Install the node on the panel server, then in Nodes → Add Node use:

  • Address: 127.0.0.1 — same machine, so no firewall work is needed
  • Name: exactly the --name you passed to the node installer
  • Port: 2083, API key: the key from the node install
  • TLS: whatever the node uses

Ports

PortWhatReachable from
2095 (or yours)Panel web UIOnly you — your browser
2083Node sync APIOnly the panel's IP
1194 (plus any extra VPN ports)OpenVPN clientsEveryone

The node installer opens ufw/firewalld automatically. If your provider has its own firewall (security groups, cloud firewalls), open them yourself. Open 1194 on both UDP and TCP, plus any additional VPN ports you configured.

Keep the node healthy

The panel probes every node on a five-minute cycle. On the transition it can message the owner on Telegram — one message when a node goes down and one when it answers again, throttled so a flapping node cannot page you every five minutes. The toggle is Settings → Alerts → "Node goes down or comes back", and it needs the bot token and owner ID from the Bot section.

On the node itself:

ovn credentials is the one to reach for when the panel entry and the node disagree: it reprints the exact name and key the panel needs, so you can compare rather than retype. The full command list is in the CLI reference.

Node data, backup and reinstall

A node has no database. Its state is plain files:

/etc/openvpn/server/     server.conf, PKI (CA, certificates, CRL), logs
/etc/openvpn/ovnode/     users/<cn>/{name,state,client.ovpn}, sessions/, usage/, scripts/
/var/lib/ovnode/<name>/  agent data

ovn backup archives /var/lib/ovnode and the OpenVPN PKI into root-only tarballs in /var/backups, keeping the newest 14 unless you pass --keep N. ovn auto-backup on adds a daily timer for it. ovn restore lists those archives and, given a name, unpacks one after taking a safety copy of the current state — and it refuses to continue if that copy cannot be made.

Reinstall and rename. Node data survives a reinstall only if you keep the same --name: a different name reads a different, empty data folder and orphans the old one on disk. ovn uninstall keeps the data; ovn uninstall --purge deletes it. Both ask first and the prompt defaults to No.

A complete disaster-recovery plan has two halves — the panel database and each node's own files. See Backups & restore for the panel side.
