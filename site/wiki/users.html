Users & subscriptions

A user is one VPN account: a numeric id, a display name, a quota, an expiry date and a device limit.

Create a user

Users → Add User. The fields are the same whether you are making one account or fifty.

FieldWhat it does
Name The display name. It is unique, and it is what the panel lists and reports on.
Expiry date After this date the account stops working. The panel sweeps for expiry-only cases every ten minutes.
Traffic quota (GB) Bytes allowed, in GB. Empty means unlimited. See Traffic limits.
Devices Simultaneous connections allowed. 0 means unlimited; 1 means a new connection takes over the old one; N rejects the N+1th at connect time.
Tag Optional free text up to 64 characters — monthly, vip, reseller-a. Shows on the row and is searchable and filterable.

Leave the rest at their defaults. Those defaults come from Settings → Defaults: default days, default traffic in GB, and default devices per new user. A fresh install ships with 30 days, 100 GB and 1 device.

How identity works

A user's numeric panel id is their OpenVPN common name: user 42 gets certificate CN 42. The node stores the display name alongside it, so usage reports can be keyed by username while the certificate layer stays numeric.

Hand the user their config

Immediately after creating a user, the panel offers the handoff: Get Config (pick a node, save the .ovpn file) or Copy subscription link. Both are available later from the download icon on the user's row.

  • Config file. A one-off .ovpn you send the user. Import it into any OpenVPN client: OpenVPN Connect on Windows and macOS, the OpenVPN app on Android and iOS, NetworkManager or openvpn --config on Linux.
  • Subscription link. A stable URL the user can re-fetch; useful when a config needs to be reissued without a new message. It is served without the secret panel path on purpose, so it can actually be shared.

The subscription URL has two shapes:

PathWhat it returns
/sub/<uuid> A page for the user, with the config and usage. Users who use a subscription-capable client fetch this.
/sub/download/<uuid>/<node> The .ovpn file for that user on that node.

The sub segment is configurable under Settings → Subscription Link, so a deployment can rename it. An invalid or deleted user gets a plain error page, and an expired user is told the subscription has expired rather than being handed a broken config.

Subscription link shows the wrong host

Subscription and download links are built from the address you open the panel with. Always log in through the public URL — https://panel.example.com/... rather than http://localhost:2095/... through an SSH tunnel — and the links you copy will carry that host.

If you serve the panel behind a proxy where the request host is wrong, pin it explicitly: set PUBLIC_URL=https://panel.example.com in .env (or OVM_PUBLIC_URL at install time, or the subscription prefix in Settings) and restart the panel.

Managing users day to day

  • Extend traffic. Adding GB to a user adds it to their current quota; leaving it at 0 keeps the quota as it was. Handy for topping someone up without changing their plan.
  • Disable, don't delete. A disabled user keeps their history and their traffic counters, and can be switched back on.
  • Filter and search. Tags and the near-quota filter make the row you want findable once the list is long.
  • Disconnect. The panel aggregates live session counts from the nodes and can drop a user's active sessions.

Deleting a node deletes its users and configs with it, and the panel warns you before it does. Deleting a user is likewise not reversible.

Other panel logins

Beyond the owner, the panel supports additional admin accounts with their own username, and can pair an account with a Telegram id. The owner row is the one created by the claim flow; the others are managed from the panel.
